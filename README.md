# miniRAG Replay Lab

A local, replayable product-knowledge RAG demo. The Python pipeline owns ingestion, chunking, BM25 retrieval, extractive answer generation, evaluation, and validation. The React app is an inspection and upload interface. **No LLM is used**, so there are no API keys or `llm_calls.jsonl` records.

## Quick start

Requirements: Python 3.10+ and Node.js 20+.

```bash
python3 rag_pipeline.py             # regenerate all artifacts from kb/ and queries.json
python3 validate.py                 # validate generated artifacts
python3 server.py                   # local API on http://127.0.0.1:8000
```

In another terminal:

```bash
npm install
npm run dev                         # React UI on http://127.0.0.1:5173
```

For a single-server build, run `npm run build` and then `python3 server.py`; the Python server serves `dist/` and `/api/*` on port 8000. `make run`, `make validate`, and `make test` are convenience commands. Generated artifacts can be deleted and rebuilt with `python3 rag_pipeline.py`.

## Inputs

- `kb/`: recursively reads UTF-8 `.txt`, `.md`, and `.markdown` files in sorted path order. Symlinks and unsupported extensions are ignored. `Title:` and `Section:` headers are parsed at the top of each file. Missing headers fall back to filename and `General`, with warnings in `artifacts/run_manifest.json`. Empty or invalid UTF-8 files are skipped with warnings; the run fails clearly if no usable documents remain.
- `queries.json`: nonempty array with unique `query_id`, `question`, and nonempty `expected_doc_titles`. Optional `ground_truth_answer_points` is schema-checked but is not fed to retrieval or answer generation.

The UI accepts document and query-file uploads. Uploaded files modify the local `kb/` and `queries.json`; click **Run pipeline** to regenerate results. A fresh interactive question uses the current documents immediately. Replacement uploads are validated before the old KB is swapped out. The UI marks evaluation results stale until a replay completes.

## Pipeline

1. Parse document metadata and retain original body text. Chunk text is a literal slice of the decoded source; `start_char` and `end_char` are character offsets into that source.
2. Build a local BM25 index over chunk text with title and section terms. Ranking ties use stable chunk IDs. No sample filename, title, question, or answer is embedded in the ranking logic.
3. Retrieve at least three chunks per evaluation query. If the corpus cannot form three nonempty chunks, stop with an actionable error.
4. Select a relevant sentence from retrieved chunks, copy it verbatim, and attach `[doc_title §chunk_id]`. At least two distinct content terms must match. A single keyword prompts for a more specific question when related material exists; it still uses the required `insufficient_context` label. A specific topic phrase that matches a retrieved document title or section, such as `document verification`, returns a short source excerpt with a citation. Other weak evidence also returns `insufficient_context`.
5. Compare expected titles with the top three retrieved titles. `hit` means all expected titles appear; `partial_hit` means some appear; `miss` means none appear.
6. Check citations against retrieval and verify that answer wording appears in cited source text. `validate.py` also checks artifact presence, JSON structure, query coverage, top-k size, scores, controlled labels, and aggregate counts.

The enforced state order is `INIT → DOCUMENTS_LOADED → DOCUMENTS_CHUNKED → INDEX_BUILT → RETRIEVAL_COMPLETE → ANSWERS_GENERATED → EVALUATION_COMPLETE → VALIDATION_COMPLETE → RESULTS_FINALISED`.

## Artifacts

`artifacts/chunks.json`, `retrieval.json`, `answers.json`, `eval.json`, `grounding_check.json`, `chunking_comparison.json`, and `run_manifest.json` are generated by every replay. The comparison runs paragraph-aware and fixed-size chunking against the same query set. It reports retrieval performance, not answer correctness.

## API

- `POST /api/run` — replay and validate the whole pipeline.
- `POST /api/ask` or `POST /answer` with `{ "question": "..." }` — retrieve and answer from the current KB.
- `GET /api/state` — source list and latest artifacts.
- `POST /api/documents` with `{ "files": [{"name":"guide.txt","content":"..."}], "replace": false }` — save documents.
- `POST /api/queries` with `{ "queries": [...] }` — replace the query set after schema validation.

This is a local development server and has no authentication. Run it only on a trusted machine.

## Tests

`make test` runs integration cases for changed filenames, UTF-8 BOM, CRLF, Unicode, nested files, missing headers, empty and invalid files, unsupported types, symlinks, a large unbroken file, invalid query schemas, upload rollback, stale-result detection, abstention, and citation tampering. `make fuzz` runs 1,000 randomized chunking cases, 100 complete replays, malformed API payloads, request-size checks, and concurrent calls with a fixed seed. Use `python3 tests/fuzz_pipeline.py --seed NUMBER` to try another reproducible seed. See `TEST_REPORT.md` for the latest run.

## Limits

Answers are extractive: they quote one source sentence rather than synthesize multi-step answers. Lexical BM25 is transparent and deterministic but can miss heavy paraphrases; the grounding threshold is conservative. The `conflicting_context` label is reserved in the vocabulary; this version does not claim to resolve contradictory sources. Retrieval evaluation checks expected document titles, while the grounding checker checks citation identity and verbatim evidence wording.
